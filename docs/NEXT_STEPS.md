## Шаг 1 — десктопный Renderer-бэкенд ✅ СДЕЛАНО

`GlRenderer` стал **кроссплатформенным** (один бэкенд: Android GLES3 и desktop
GL 3.3). Контекст/своп/размер — платформенные (`#ifdef __ANDROID__` EGL, иначе
GLFW снаружи + `setSurfaceSize`), версия шейдеров через макрос `GLSL_VERSION`
(`300 es` / `330 core`), GL-функции на десктопе грузятся через `GlApi.h` (свой
мини-загрузчик). Интерфейс: `Renderer::init(window, glGetProc)` + `setSurfaceSize`,
`ANativeWindow` — forward-declare. Десктоп-клиент теперь использует общий `Scene`
+ `FileAssetSource` и рендерит ту же сцену/лису (скиннинг/бленд/материалы/HUD/ImGui).
Собрано и запущено (NVIDIA GTX 1070, GL 3.3.0), подключается к серверу.

Ввод в ImGui на десктопе ✅ сделано: подключён официальный platform-бэкенд
`imgui_impl_glfw` (мышь/клавиатура/скролл/курсоры). Renderer-бэкенд
`imgui_impl_opengl3` остался в `GlRenderer` (общий), platform-бэкенд — за его
пределами: Android кормит ввод вручную (touch→mouse), десктоп — через glfw.
Само содержимое панели вынесено в общий модуль `GameUi.{h,cpp}` (тянет только
imgui + `Scene`, не ломает платформонезависимость ядра) и одинаково на телефоне
и ПК. WASD гейтится по `io.WantCaptureKeyboard`, поле IP — `InputText` + свой
кейпад для тача. Внешний вид панелей/кнопок — `UiSkin` + `assets/ui/` (см.
ARCHITECTURE §3). ✅ Текстура ящика `assets/textures/crate.png` — сделана (процедурный
генератор `assets/textures/gen_crate.py`, Pillow: доски + рама + металлические уголки).

## Шаг 2 — порт Vulkan-бэкенда под контракт RenderFrame ✅ СДЕЛАНО (десктоп + Android)

**Цель:** второй бэкенд под тем же `Renderer`/`RenderFrame`. Делаем **десктоп-first,
кроссплатформенно**: разрабатываем и запускаем на десктопе (GLFW+Vulkan, флаг
`--vk`), ядро потом переиспользуем на Android. Причина — Vulkan без запуска почти
не заводится, а Android здесь не запускается; на десктопе итерируем.

**Тулчейн:** заголовки Khronos вендорены в `third_party/vulkan/`; функции грузятся
динамически через `glfwGetInstanceProcAddress` (загрузчик `VkApi.*`) — vulkan-1.lib
для запуска не нужен. Шейдеры GLSL→SPIR-V — через `glslc` (SDK:
`C:\VulkanSDK\1.4.350.0\Bin\glslc.exe`, либо NDK `shader-tools/`).
**Validation layers:** установлен Vulkan SDK (`C:\VulkanSDK\1.4.350.0`), слои
`VK_LAYER_KHRONOS_validation` включаются автоматически при наличии + debug messenger
шлёт сообщения в лог. Фаза 0 проходит валидацию чисто.

**Фазы:**
- ✅ **Фаза 0** — instance/device/swapchain/render pass/present, очистка экрана
  (`VulkanRenderer.cpp`, `VkApi.*`). Собрано и запущено на десктопе (`--vk`).
- ✅ **Фаза 1** — пайплайн Lit + вершинные/индексные буферы (host-visible) + **depth** +
  per-object матрица (push-константа) + frame-UBO (viewProj/свет, дескриптор-сет на кадр)
  + коррекция клип-пространства GL→Vulkan (`vulkanClipFix`). Шейдеры `cpp/shaders/lit.*`
  → SPIR-V через `glslc` (CMake), грузятся из `assets/shaders/vk/`. Окружение рисуется,
  валидация чиста. Cull=NONE (winding — потом). Материалы пока только цвет (текстуры — Ф2).
- ✅ **Фаза 2** — текстуры (staging → device-local image, барьеры layout, сэмплер
  LINEAR+REPEAT, дефолтная белая 1x1) + три пайплайна Lit/Unlit/Phong (общий
  pipeline layout: set 0 = Frame UBO, set 1 = albedo материала, push = model+color).
  Шахматка на полу и блики Phong рисуются, валидация (вкл. synchronization) чиста.
- ✅ **Фаза 3** — инстансинг. Модельная матрица — per-instance атрибут `iModel`
  (binding 1, локации 3–6) вместо push-константы; push теперь только цвет (фрагментный).
  `renderFrame` батчит `frame.items` по (mesh, material), раскладывает матрицы в
  per-frame инстанс-буфер (host-visible, `kMaxInstances`=512) и рисует каждый батч
  одним `vkCmdDrawIndexed(instanceCount, firstInstance=...)`. Кольцо 48 кубов = 1 draw
  (всего ~8 draw вместо 55). Валидация чиста.
- ✅ **Фаза 4** — скиннинг (лиса). Кости — в per-frame **SSBO** (set 2, `mat4 bones[]`,
  `kMaxBones`=512), смещение модели в `uBoneOffset` (push). Отдельный skinned-пайплайн
  и layout (set0 Frame + set1 albedo + set2 bones; push = model+color+boneOffset,
  VERTEX|FRAGMENT); vertex-формат `SkinnedVertex` (16 float). `renderFrame` раскладывает
  кости всех `frame.skinned` в SSBO и рисует каждый объект своим `uBoneOffset`. Текстуры
  скиннинга — свои set 1 (`textureSets_` + `whiteSet_`). Лиса рисуется, валидация чиста.
- ✅ **Фаза 5** — HUD + ImGui. HUD: атлас `Font` → текстура (NEAREST/CLAMP-сэмплер),
  свой пайплайн (alpha-blend, без depth), per-frame динамический буфер квадов, push =
  screen+color; NDC без Y-флипа (Vulkan Y вниз). ImGui: `imgui_impl_vulkan` c
  `IMGUI_IMPL_VULKAN_NO_PROTOTYPES` + `ImGui_ImplVulkan_LoadFunctions` (наш загрузчик
  `vkApiLoader`), `DescriptorPoolSize>0` (пул создаёт бэкенд), `PipelineInfoMain.RenderPass`;
  контекст создаёт `VulkanRenderer`, platform-бэкенд `ImGui_ImplGlfw_InitForVulkan` — в main.
  Панель `GameUi` та же, что на GL/Android. Полный паритет с GL, валидация чиста.
- ✅ **Рантайм-переключение бэкенда (десктоп)** — кнопки OpenGL/Vulkan в панели
  `GameUi` (`GameUiState.backend`/`requestBackend`/`vulkanAvailable`; кнопка текущего

- ✅ **Фаза 6 — Android (проверено на устройстве: работает корректно).** Ядро
  (`VulkanRenderer`/`VkApi`/шейдеры/пайплайны) переиспользовано;
  отличия под `#ifdef __ANDROID__`:
  - surface — `vkCreateAndroidSurfaceKHR` (+ расширение `VK_KHR_android_surface`);

  - **Готча линковки решена:** `libvulkan` УБРАН из линковки (`dl` вместо него),

    экспортами libvulkan (duplicate symbol).
  - `app/.../CMakeLists.txt`: добавлены `VulkanRenderer.cpp`/`VkApi.cpp`/`imgui_impl_vulkan.cpp`

  **Ориентация:** `preTransform` на Android — IDENTITY (не `currentTransform`), иначе

## Шаг 2.5 — физика: кинематический контроллер на Jolt ✅ СДЕЛАНО (десктоп + сервер + Android)

**Цель:** коллизии/границы/прыжок для персонажа. Только **кинематика** (Jolt
`CharacterVirtual`), динамика твёрдых тел не нужна. Движок — **Jolt Physics**
(вендорен в `third_party/jolt`, тег **v5.6.0**).

**Архитектура (важно — диктуется мультиплеером):**
- Движение живёт в `Character::simulate`, вызывается в трёх местах: локальное
  предсказание, реплей реконсиляции ([Scene.cpp](../app/src/main/cpp/game/Scene.cpp)) и
  сервер ([Net.cpp](../app/src/main/cpp/engine/net/Net.cpp)). Коллизии должны считаться **тем же
  кодом** на клиенте и сервере — иначе предсказание у стены будет «резинить».
- План: `CollisionWorld` (обёртка Jolt, платформонезависима, рядом с `Character`/
  `Scene`/`Net`) держит статику арены и `CharacterVirtual` на игрока (по хэндлу).
  `Character::simulate(dt, in, CollisionWorld*)` двигает через мир (collide-and-slide),
  а не `position +=`; `Character` остаётся POD (состояние контроллера — в мире).
- **Сервер сейчас безмировой** (знает только позиции) — для коллизий ему нужна та же
  геометрия: расширить `.scene` директивами `collider ...`, сервер грузит тот же файл
  через `FileAssetSource`.

**Подключение Jolt (готчи — соблюдать):**
- Через **родной CMake-таргет** `Jolt` (`add_subdirectory(third_party/jolt/Build ...)`
  + `target_link_libraries(<цель> Jolt)`). Все `JPH_*`-дефайны и include у таргета
  **PUBLIC** → у либы и потребителя совпадают автоматически (рассинхрон = порча памяти).
  Руками дефайны/пути НЕ прописывать.
- Опции перед `add_subdirectory` (во всех трёх целях): `JPH_USE_DX12/VK/MTL OFF`
  (GPU-compute не нужен и тянет dxc/glslc; на Android VK по умолчанию ON — обязательно
  выключить), `ENABLE_ALL_WARNINGS OFF` (иначе `/WX` ломает сборку на новом MSVC),
  `INTERPROCEDURAL_OPTIMIZATION OFF` (LTO мешает миксу со static; на ARM ломает кодоген),
  `ENABLE_INSTALL OFF`; на MSVC — `USE_STATIC_MSVC_RUNTIME_LIBRARY OFF` (/MD как у нас).
  CPU-compute оставляем (чистый C++, нужен Hair — он в исходниках безусловно).
- **`CMAKE_BUILD_TYPE` обязателен** — у `build.bat` был пуст, Jolt без конфига не
  собирается: в `desktop/build.bat` и `server/build.bat` добавлен `-DCMAKE_BUILD_TYPE=Release`.
- В коде: `#include <Jolt/Jolt.h>` ПЕРВЫМ; `using namespace JPH::literals;` для суффикса `_r`.

**Фазы:**
- ✅ **Фаза 0 — сборка на всех трёх целях + smoke.** Проверено на устройстве/десктопе/
  сервере (Jolt собирается и линкуется). Временный `PhysicsSmoke` уже удалён — заменён
  `CollisionWorld`.
- ✅ **Фаза 1+2 — `CollisionWorld` + статика из сцены + контроллер игрока (клиент, офлайн).**
  Сделаны одним заходом (Фаза 1 сама по себе без видимого результата).
  - `CollisionWorld.{h,cpp}` — обёртка Jolt (pimpl, Jolt НЕ течёт в ядро): статичные
    боксы + кинематические капсулы (`CharacterVirtual`, `Update` без гравитации).
  - Формат сцены расширен: `collider box center <x y z> half <hx hy hz>` и у `player`
    ключ `capsule <radius> <cylHalf>` (по умолчанию 0.3 0.3). `SceneDesc`/`SceneLoader`.
  - `Character::simulate(dt, in, CollisionWorld*)` двигает через `moveCharacter`
    (collide-and-slide), fallback без мира — прямое интегрирование. `Character` — POD,
    хэндл контроллера в поле `collider`; состояние капсулы живёт в мире.
  - `Scene` владеет `CollisionWorld` (unique_ptr, `~Scene` в .cpp), строит коллайдеры

  - `default.scene`: пол + 4 стены-границы (±12) + 3 куба-препятствия (8 коллайдеров).
  - **Проверено:** headless-самотест `vbase_server --selftest` — лобовое (x упирается

    стартует с физикой без краша, `Физика: 8 статичных коллайдеров`. Визуальный проход
    WASD по десктопу — за пользователем (инъекция клавиш в окно из автоматизации ненадёжна).
    Капсула — в игровом масштабе, не в масштабе крошечной лисы (scale 0.03); тюнится

## Шаг 3 — доведение неткода

- ✅ **Delta-сжатие снапшотов** — сделано (Quake3-подход, весь в `Net.cpp`, `Scene` не
  тронут). Клиент подтверждает последний применённый тик (`InputMsg.ackTick`); сервер
  шлёт дельту относительно ПОДТВЕРЖДЁННОГО тика (устойчиво к потерям UDP), а не последнего
  посланного. `SnapshotHeader`: `baseTick` (0 = полный) + `changedCount`/`removedCount`,
  далее изменившиеся `EntityState` и id исчезнувших. Кольцо истории снапшотов (64 тика ≈ 2 c)
  на **обеих** сторонах: сервер — база для дельт, клиент — чтобы применить дельту на нужную
  базу (не на «текущее», иначе рассинхрон при потере ack). База выпала из кольца →
  сервер шлёт полный (self-heal). «Изменилось» — по эпсилону 1e-3 (гасит асимптотику
  speed01/animParam). Клиент реконструирует полный `states()` — поэтому `Scene`/реконсиляция
  без изменений. **Проверено:** `--selftest` — реконструкция верна (авторитетный x=1.43),
  в простое дельта схлопывается (`changed=0`); десктоп без регрессий; `Net.cpp` под aarch64 чисто.
- **Lag compensation**: перемотка чужих на момент действия. **Только когда появится

## Пасфайндинг мобов (поле потока) ✅ СДЕЛАНО

Мобы ходят по **полю потока** (мультиисточниковый BFS на клеточной навсетке), а не
steer-to-target. Живёт в `game/FlowField.*` (+ `game/Grid.h`); строит и опрашивает
`GameWorld` (сервер-only — клиент рисует по снапшотам, протокол не менялся).

- **NavGrid** — занятость клеток (до 512², константа `kMaxSide`). Растеризуются статика
  сцены (с клиренсом под радиус капсулы) и **футпринты зданий** (`CollisionWorld::addBox/
  removeBox` в рантайме; одна геометрия `footprintBox` для физики И occupancy). Спавнер не блокирует.
- **FlowField** — BFS от целей; направление в клетке = **градиент поля расстояний** с
  устойчивой базой (спуск к соседу-минимуму) — сглаживает «лесенку», не режет углы сквозь
  два блока, не застревает на «гребнях». Хранит только дистанции (uint16).
- **Цели по типу моба** (`config/enemies.cfg`, ключ `target core|building`;
  `CharacterDesc::MobGoal`): рашеры → к ядру, «ломатели» → к ближайшей постройке.
  **Фолбэк:** ядро недостижимо → моб ломает ближайшее здание. Это снимает костыль с
  ограничения построек — базу можно запечатать наглухо, её прогрызут.
- **Два поля на команду** (`toCore`/`toBuildings`); пересчёт **ленивый** — только при смене
  построек (`mapDirty`) и только для команд с живыми мобами (`ensureFlowField`): в PvE 2 BFS
  вместо 8. Стоимость ребилда на 400² ≈ 4 мс/поле (замер в `--densetest`).
- **Тесты:** `vbase_server --selftest` → `PathTest` (стена/фолбэк/ломатель/масштаб 512);
  отдельная команда `vbase_server --densetest` (серпантин / запечатка / диагональ-щель / перф
  + детектор застреваний). *TODO-решение: свернуть S1–S3 в основной suite или оставить отдельно.*
- **Готча:** `reachable()` «щедрый» (сосед-в-поле = true, чтобы моб на футпринте не считался
  тупиковым) — моб, замурованный так, что выход только по диагонали, не переключится на снос.
  На практике недостижимо (в такой карман не войти).

## Бесконечные волны спавнера ✅ СДЕЛАНО

Спавнер с `wavesize>0` (`config/buildings.cfg`) плодит врагов **волнами без конца**: волна из
`curWaveSize` врагов через `interval`, затем пауза `wavepause`, затем следующая (размер растёт
на `wavegrow` за волну). `wavesize 0` = легаси-режим (спавн до `max`/cap, затем стоп) —
built-in селф-тесты его не трогают (специи строят `BuildingSpec` в C++ без wave-полей).

- Поля `waveSize/wavePause/waveGrow` протянуты `BuildingInfo`→`BuildingSpec`→`Entity`
  (+ рантайм `waveIndex/spawnedInWave`); логика — стейт-машина в `GameWorld::step`
  (спавн волны по `rate` → пауза → следующая волна). Протокол не менялся (параметры серверные).
- В бесконечном режиме **PvE = выживание**: спавнер «не отработал» → `waveCleared_` не
  срабатывает (победы по волнам нет), проигрыш = ядро пало → матч-рестарт (`matchrestart`).
  Это же снимает стейлмейт PvP (волны не иссякают).
- Тест `--selftest` `WaveTest`: бесконечный спавнер за ~4 c даёт ~24 врага (> легаси-cap 12,

## Разнообразие башен/ловушек + апгрейд ✅ СДЕЛАНО (protocol v7)

TD-глубина защиты: вместо одной башни — **ростер видов** (`config/towers.cfg`) + **тир-апгрейд**
и **снос с возвратом**. Виды: **Стрелок** (одиночная цель), **Мороз** (замедляет),
**Пушка** (AoE-сплэш по площади), **Огонь** (поджог/DoT), **Шипы** (напольная ловушка).

- **Модель данных.** `game/TowerRoster.{h,cpp}` (`TowerDesc` + парсер `loadTowerRoster`, по образцу
  `CharacterRoster`): id/name, `class tower|trap`, cost/hp/rate/range/damage, `effect none|slow|
  splash|burn` (+ `slow`/`dur`/`splash`/`burn`), `maxtier` и множители тира (`dmgmul/rangemul/
  ratemul/upcost`), `color` (тинт визуала). Индекс записи = **вид (kind)** — сетевой контракт.
  `SceneDesc.towerTypes`; грузится и клиентом (`Scene::build`), и сервером (`server/main.cpp`),
  санитизируется в `validateSceneDesc`. Класс записи (`entity`) сам решает `EntityType`.
- **Тип-подтип.** Башни-стрелки — `EntityType::Tower` c видом в `charType` (как тип у мобов).
  Ловушка — новый **`EntityType::Trap`**: `isBuildingType`=да (занимает клетку), `blocksPath`=нет
  (мобы проходят по ней — в этом смысл). Тир хранится на сущности (`Entity.tier`), в сеть едет
  упакованным: у Tower/Trap `EntityState.charType` = вид (младший ниббл) | тир<<4 (старший).
  Размер `EntityState` не изменился (52 б) — только семантика поля.
- **Бой (сервер, `GameWorld::step`).** Башня по кулдауну шлёт снаряд (несёт вид в `charType`);
  при попадании — прямой урон + эффект вида: **мороз** ставит `slowTimer/slowFactor` (режет
  скорость в движении моба), **огонь** — `burnTimer/burnDps` (DoT тикает в цикле мобов),
  **пушка** — доп. урон по всем врагам в `splashRadius` вокруг цели. Ловушка (Trap) снаряда не
  шлёт — по кулдауну бьёт AoE всех врагов в радиусе под собой. Снаряд героя помечен `charType=0xFF`
  (не вид → без эффектов + свой цвет болта).
- **Апгрейд/снос.** `tryUpgrade` (тир+1 за `cost*upcost*tier`, растит урон/радиус/скорострельность;
  на максимуме — отказ), `tryDemolish` (свои Tower/Trap/Generator/Storage; возврат
  `spent*0.6`). `Entity.spent` копит вложенное. Сеть: `MSG_BUILD` получил байт вида; новые
  `MSG_UPGRADE`/`MSG_DEMOLISH` (id цели), тот же кэп «действий стройки за тик». Авторитет и
  валидация (владение/тир/ресурс/класс↔тип, античит) — на сервере; легаси-фолбэк: без `towers.cfg`
  рантайм-башня берётся из `BuildTemplate` сцены (вид 0), ловушка недоступна.
- **Клиент.** Палитра стройки (`BattleScreen`) — Генератор/Хранилище + виды из ростера (имя+цена,
  `beginBuild(entityType, kind)`). Панель выделенного (`windows/BuildingInfo`) для защиты: тир X/Y,
  «Улучшить (цена)», «Снести (+возврат)» (возврат оценивается клиентом детерминированно, как сервер).
  Визуал: башня — пилон, тинт по виду (тинт-материал поверх атласа) + масштаб по тиру; ловушка —
  низкая плита; болт — цвет вида. Ловушка пикается/строится (призрак — плита), клетку занимает.
- **Тесты.** `--selftest` `[Towers]`: сборка по ростеру, античит класса (Trap↔вид-башни отклонён),
  рост тира + трата ресурса + отказ на максимуме, снос с возвратом, занятость клетки ловушкой,
  легаси-фолбэк без ростера. Эффекты (мороз/сплэш/огонь) идут по общему пути снаряда — визуал
  проверяется в игре. Всё зелёно: server/desktop/editor BUILD_OK, `--selftest` 32/32 (exit 0),
  aarch64 `-fsyntax-only` чисто, десктоп-смоук ALIVE_5S, `towers.cfg` парсится (5 видов).
- **Осталось по фиче (не входило):** морозная/огненная ловушка (эффект у Trap уже прокинут —
  `applyTowerEffect` на тике; нужен лишь вид в `towers.cfg`); отдельные модели башен по виду
  (сейчас общий пилон + тинт); визуальный маркер «заморожен/горит» на мобе (нужен сетевой бит).

**✅ СДЕЛАНО (стартовое меню → выбор персонажа → бой; сетевой, protocol v5).** Ростер как данные
(`config/characters.cfg` + `game/CharacterRoster.*`); `Scene` держит РЕЕСТР моделей (`chars_`, все 5
грузятся в `build`, выбор индексом — без утечек GPU), `makeCharItem(index,...)`. Новый экран
`UiMode::CharacterSelect` (`screens/CharacterSelectScreen.*`) с 3D-превью (крутится) — рендер-путь
выбирает главный цикл по `GameUi::mode()` (`renderCharacterPreview`/`renderMenuBackdrop`; мир скрыт
за меню). Поток: `HomePanel` (В бой/Host/Join) → CharacterSelect → Battle. Сеть: `EntityState.charType`
+ `InputMsg.charType` (аплинк без засорения `Character`: `NetClient::setCharType`), `GameWorld.Entity.charType`;
чужие рисуются своей моделью. attack-клип per-character (mage→Spellcast_Shoot, barbarian→Chop, knight→Slice,
rogue→Dualwield). Desktop: авто-join убран (заход через меню), для тестов флаг `--join`.

**Разные статы у героев** — сделаны: `characters.cfg` задаёт `hp`/`speed` на героя (варвар танк/медленный,
разбойник быстрый/хрупкий, …). Сервер грузит `characters.cfg` → `SceneDesc.heroTypes` → `GameWorld.heroTypes_`;
`setHeroCharType` при первом получении/смене charType зовёт `applyHeroStats` (hp/maxHp + `move.maxSpeed`).
Клиент синхронно ставит `player_.maxSpeed` из `chars_[i].speed` в `selectCharacter` (иначе предсказание
расходилось бы с сервером) и `localMaxHp_` для HUD. **Авто-атака героя — сделана** (см. «Авто-атака героя» ниже): damage/atkint/range/ranged из `characters.cfg` теперь используются.

камера-подставка/фон для превью (сейчас чистый фон).

**✅ СДЕЛАНО (мобы-скелеты).** Враги спавнеров рисуются скиннинг-моделями **KayKit Skeletons (CC0)**

charType % mobs_.size(), …)`, walk-анимация, facing с сервера; сервер выставляет `enemy.charType`
= `spawnedCount % 4` (разнообразие через уже существующее поле `EntityState.charType`). `hide eyes`
(2-й материал Glow без текстуры). Нет `enemies.cfg` → откат на старый generic-меш.

ростера больше не перебивается fallback с меньшим индексом).
**Анимация смерти мобов** — сделана (клиентская косметика): исчез из снапшота в фазе Playing →
локальный «труп» `DyingMob` проигрывает клип смерти (скелеты рассыпаются — `Death_C_Skeletons`).

recenter+scale+yaw в вершины (`bakeStaticMesh`) — generic-рендер только translation. core→золотой
сундук, spawner→врата-арка, tower→колонна-шпиль. Тем же путём можно дать модель ЛЮБОМУ зданию.
**Снаряд башни** — сначала был клиентской косметикой, ЗАТЕМ заменён серверной сущностью
(см. ниже «Снаряды башен — серверная сущность»); клиентская симуляция снаряда удалена.

**Снаряды башен — серверная сущность** (protocol v6): новый `EntityType::Projectile`. Башня спавнит

клиент рисует remote-снаряды болтом (клиентская косметика снаряда убрана). Константы снаряда — в
`GameWorld.cpp`. Модели врагов/зданий и бой мобов — готовы.

3. Клиент выбирает персонажа (экран/панель) → нужен runtime-перезагруз скиннинг-модели

## Кастомные glTF-объекты в сцене (декор уровня) ✅ СДЕЛАНО

Чтобы собирать красивые уровни из готовых CC0-паков (KayKit/Quaternius/Kenney — все отдают GLB),
формат сцены умеет статичные glTF-пропсы:

- **Загрузчик** `loadGltfStatic` (`engine/assets/Model.*`): читает geometry всех примитивов всех
  мешей в один `MeshData` (pos/normal/uv), запекая мировые трансформы узлов; вытаскивает встроенный
  albedo-атлас (`decodeImageBuffer`). Без скелета/анимаций (в отличие от `loadGltfModel`). Гарды
  `cgltf_validate` (P2-13) как у скиннинг-загрузчика.
- **Директива сцены** `object model <path.glb> [tex <p>] [shader lit|unlit|phong] [pos/rot/scale/spin]`
  (и `ring model …`). Парс — `SceneLoader` (форма отличается вторым токеном `model`); инстанс — в
  `Scene::build`: mesh+material (со встроенной или внешней текстурой) кэшируются по `path|tex|shader`,
  ставятся `GameObject`'ом (pos/rot/scale/spin как у процедурных). Не загрузилась → пропуск + warn.
- **Использование:** `.glb` в `assets/models/`, строка в `.scene`, коллайдер (если надо) — отдельной
  `collider box` (визуал ≠ физика). Пример (закомментирован) — в `scenes/default.scene`; синтаксис —
  ARCHITECTURE §5.1.
- **Проверено:** desktop `BUILD_OK`; сервер (SceneLoader/SceneDesc) `BUILD_OK` + `--selftest` 30/30;
  `Model.cpp`/`Scene.cpp`/`SceneLoader.cpp` aarch64 `-fsyntax-only` чисто; рантайм — `object model
  models/Fox.glb` реально загрузился на старте (`glTF static: … 1728 верш. +текстура`, без краша).
- **Дальше по желанию:** авто-коллайдер из AABB модели (сейчас коллайдер задаётся вручную);
  инстансинг-рендер одинаковых пропсов (сейчас каждый — свой `GameObject`, но mesh/material общие).

### Поверхность земли + «красивый край» (шейдер Ground + горизонт) ✅ СДЕЛАНО

Проблема: пол — плоский квад с шахматкой и резким обрывом в тёмный фон («чернота снаружи»); туман
пробовали — мылил всю картинку (экспонента от нуля). Решение (вариант A, БЕЗ общего тумана):

- **Шейдер `ShaderType::Ground`** (`shaders/ground.frag` GL + `cpp/shaders/ground.frag` VK→spv): как
  Lit (Ламберт+тень+ambient+текстура), но **дальняя земля плавно тонируется в цвет горизонта**
  (`uFogColor`, линейный) по горизонтальной дистанции от камеры (`smoothstep(55..120)`). Игровая
  зона (<55 ю) остаётся резкой — мыла нет. Тинт **только у пола** (материал с шейдером `ground`),
  пропсы/юниты — Lit, не тонируются. UBO не менялся (переиспользуем `uFogColor`/`uViewPos`), так что
  Vulkan — только новый pipeline + spv (массив `pipelines_` расширен до `ShaderType::Count`).
- **Фон-очистка = цвет горизонта всегда** (было: тёмно-синий при выключенном тумане): `clear =
  pow(uFogColor, 1/2.2)`. Дальняя земля уходит в тот же цвет → край сливается с фоном без обрыва.
- **Директива сцены `horizon <r g b>`** (sRGB) → `SceneDesc.horizonColor` → `frame.fogColor`
  (линейный). Дефолт `0.07 0.07 0.12` = прежний тёмный фон, поэтому сцены без `horizon` не меняются.
  Пути меню/превью фон не задают → дефолт `RenderFrame.fogColor` (= тот же тёмный).
- **Текстуры земли** — процедурные бесшовные (`textures/gen_ground.py`, тороидальный fbm):
  `grass.png` (трава) и `dirt.png` (утоптанная земля, под будущую дорожку). Материал пола —
  `material floor ground color 1 1 1 tex grass`, `mesh ground plane 240 60` (большой, тайл ~4 ю).
- **`forest_demo`**: большой травяной пол (ground), `horizon 0.58 0.66 0.70`, лес-рамка по периметру
  (уже была) + туман выключен → живая поверхность, край уходит в дымку горизонта без черноты.

**Проверено:** GL — шейдер компилится, трава грузится, сцена ALIVE; **Vulkan** — init на GPU,
pipeline земли создан, ноль validation-ошибок, ALIVE; server/editor BUILD_OK; `--selftest` 33/33
(round-trip идемпотентен с новым `horizon`/`ground`); aarch64 `SceneLoader`/`Scene` чисто.
**Лёгкий рельеф земли (Tier 1: нормал-карта) ✅ СДЕЛАНО:** «фейковый» рельеф через освещение —
без геометрии/физики (никто не «висит»). Шейдер `ground` уже сэмплит нормал-карту (`mapNormal`),
материалы принимают `normal <tex>` — так что **кода не трогали**: `gen_ground.py` генерит органичную
бесшовную tangent-space нормалку `ground_n.png` (из fbm-высоты, R=наклон X / G=наклон Z / B=вверх),
`forest_demo` подключает её к полу (`material floor ground ... tex grass normal groundn`). Плоская
земля ловит свет как неровная (комья/борозды). Крутизна — параметр `strength` в генераторе (сейчас
1.4). Настоящие бугры в силуэте (Tier 2, подразбитый меш) — отдельно, если Tier 1 мало.

**Дорожка-тропа ✅ СДЕЛАНО:** добавлен прямоугольный plane-меш (`makePlaneRect` + `MeshSpec::Rect` +
директива `mesh <name> rect <sizeX> <sizeZ> [uvX] [uvZ]`, серия/парс/сериализация). В `forest_demo`
по центру обеих полос лежит утоптанная дерт-дорожка (текстура `dirt.png`, два `rect`-объекта чуть
выше травы, форма повторяет Г-маршрут) — визуально ведёт от спавнеров к базе. Чисто декор (без
коллайдера). **Дальше по желанию:** раскатать травяной пол+горизонт(+дорожку) на прочие сцены;
лёгкий рельеф (heightfield, с оговоркой про физику).

## Выбор персонажа в главном меню (до коннекта) ✅ СДЕЛАНО

**Был баг:** коннект случался раньше выбора героя — `Host`/`Join` в `HomePanel` подключались, а
персонажа выбирали уже в `Lobby`. `GameWorld::setHeroCharType` коммитит тип ОДИН раз по первому
полученному инпуту (анти-хил гард `heroStatsApplied`), поэтому фиксировался дефолтный тип, а поздний
выбор в лобби игнорировался (симптом: чужой клиент рисуется не той моделью).

**Решение (чисто клиентское, сервер и анти-хил не тронуты):** выбор героя перенесён в **главное меню
`HomePanel`** — до `Host`/`Join`. `Scene::selectCharacter` уже зовёт `NetClient::setCharType`, а
`connect()`/`disconnect()` `charType` **не сбрасывают**, поэтому выбранный до коннекта тип уходит
серверу первым же инпутом и коммитится корректно.

- **`HomePanel`**: секция «Герой» (тот же ростер `Scene::rosterCount/rosterName`, запись в
  `GameUiState.charIndex` — персист между запусками). В активной сессии пикер **заблокирован**
  (тип уже закоммичен) с подсказкой.
- **`LobbyScreen`**: пикер героя активен **только до коннекта** (путь «В бой»→Lobby без host);
  после подключения — read-only + подсказка «сменить героя — в меню до подключения». 3D-превью и
  статы остаются как подтверждение.
- Анти-хил (`heroStatsApplied`) не тронут — смена типа в активном матче по-прежнему блокируется.
- **Тест** `--selftest` `[CharSelect]`: два клиента ставят `setCharType` ДО `connect` — сервер
  коммитит разные типы, каждый клиент видит свой И чужой heroType верно (регресс на порядок
  setCharType/connect). Зелено: server/desktop/editor BUILD_OK, `--selftest` 33/33 (incl.
  CharTypeHeal/RestartStats/PvP/Coop), aarch64 чисто, десктоп-смоук ALIVE_5S. Мультиплеер (два
  клиента видят правильные модели друг друга) — проверяется вживую.

## Принцип

Всё «над рендером» и «над платформой» держим платформонезависимым. Новые фичи —
как данные в `RenderFrame`/`Scene` и реализации за интерфейсами (`Renderer`,
`AssetSource`), а не хардкодом в конкретный бэкенд.
