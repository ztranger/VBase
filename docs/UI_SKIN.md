# UI Skin — как рисовать текстуры под 9-slice

Руководство для художника/разработчика: как готовить PNG для `UiSkin`
(`app/src/main/cpp/UiSkin.*`, ассеты в `app/src/main/assets/ui/`).

Код и шрифт ImGui не трогаем — меняется только картинка.

---

## 1. Какие файлы нужны

| Файл | Назначение | 9-slice? |
|------|------------|----------|
| `panel.png` | Рамка окна | **Да** |
| `button_normal.png` | Кнопка обычная | Нет (растягивается целиком) |
| `button_hover.png` | Кнопка под курсором | Нет |
| `button_active.png` | Кнопка нажата | Нет |

Путь: `app/src/main/assets/ui/`. Формат: **RGBA PNG**. Если файла нет —
подставляется процедурная заглушка.

Перегенерация заглушек: `python app/src/main/assets/ui/gen_ui_skin.py`.

---

## 2. Что такое 9-slice (для панели)

Текстура делится на **9 частей**. При растягивании окна:

```
┌────────┬────────────────┬────────┐
│ угол   │  верх (тянется │ угол   │
│ фикс.  │  по ширине)    │ фикс.  │
├────────┼────────────────┼────────┤
│ левый  │                │ правый │
│ край   │  центр         │ край   │
│ (высота│  (тянется      │ (высота│
│ тянется│   везде)       │ тянется│
├────────┼────────────────┼────────┤
│ угол   │  низ (тянется  │ угол   │
│ фикс.  │  по ширине)    │ фикс.  │
└────────┴────────────────┴────────┘
```

- **Углы** — не масштабируются (орнамент, болты, скругления).
- **Края** — тянутся только вдоль стороны.
- **Центр** — заливка под контент (обычно полупрозрачная/тёмная).

В коде граница реза задаётся так (`UiSkin::load`):

```text
borderTexels = min(width, height) * 0.25
```

То есть **рамка = 25% меньшей стороны** текстуры. Это жёсткое правило текущего
скина: рисуй арт так, чтобы вся «рамка» укладывалась в эти 25%, а внутри — только
ровная заливка центра.

## 3. Панель (`panel.png`) — размеры и отступы

### Рекомендуемый размер

| Параметр | Значение | Почему |
|----------|----------|--------|
| Размер | **128×128** (или 256×256) | Степень двойки, удобно для GPU |
| Формат | RGBA PNG | Нужна прозрачность по желанию |
| Border (рез) | **25% меньшей стороны** | Зашито в коде |
| На 128×128 | **32 px** со всех сторон | `128 * 0.25 = 32` |
| На 256×256 | **64 px** со всех сторон | то же правило |

### Схема пикселей (128×128)

```
         32px        64px         32px
      ├────────┼──────────────┼────────┤
  32px│  UL    │     TOP      │   UR   │  ← углы + верхняя кромка
      ├────────┼──────────────┼────────┤
  64px│ LEFT   │    CENTER    │ RIGHT  │  ← центр = фон контента
      ├────────┼──────────────┼────────┤
  32px│  DL    │    BOTTOM    │   DR   │
      └────────┴──────────────┴────────┘
```

### Чем руководствоваться при рисовании

1. **Вся декоративная рамка** (обводка, градиент металла, болты в углах) должна
   лежать **внутри** полосы border (на 128 — в первых/последних 32 px).
2. **Центр (64×64 на 128)** — однотонная или слабо текстурированная заливка.
   Сюда ляжет title + контент. Не рисуй здесь уникальный орнамент — он размажется.
3. **Углы** — весь «характер» рамки. Они не растягиваются.
4. **Края (TOP/BOTTOM/LEFT/RIGHT)** — повторяемый или гладкий паттерн вдоль оси.
   Резкий уникальный рисунок посередине края при растягивании окна «поедет».
5. **Внутренняя кромка** (линия между рамкой и центром) — рисуй **на границе**
   border/центра (на 128 — около x,y = 32 и 96), чтобы при любом размере окна
   линия оставалась ровной.
6. **Не клади важный арт вплотную к внешнему краю** на 1 px — фильтрация
   (bilinear) слегка подмешает соседние тексели; оставь 1–2 px «безопасной» кромки
   или делай край непрозрачным однотонным.
7. Альфа: центр может быть полупрозрачным; углы/рамку лучше почти непрозрачными,
   иначе за ними будет просвечивать сцена.

### Что будет на экране

Код дополнительно рисует **полосу title** поверх центра (не часть PNG).
Контент сидит с отступом `frame + pad` от края окна — не рисуй «поле для текста»
в PNG title: title программный.

## 4. Кнопки (`button_*.png`)

Кнопки **не** режутся 9-slice: текстура растягивается на весь прямоугольник виджета.

| Параметр | Рекомендация |
|----------|--------------|
| Размер | **128×48** (или 96×40) |
| Состояния | Три файла одного размера и одной формы |
| Скругления | В альфе по углам (прозрачный фон снаружи «таблетки») |
| Текст | **Не рисовать** на текстуре — подпись рисует ImGui шрифтом |

Советы:

- Одинаковый силуэт у normal / hover / active — меняй только цвет/яркость.
- Hover светлее, active темнее (или наоборот — но консистентно).
- Оставь запас 4–8 px от края «таблетки» до важного блика — при мелких кнопках
  края сильнее мнутся растягиванием.
- Если позже понадобится 9-slice для кнопок — это отдельное изменение кода;
  сейчас достаточно трёх цельных картинок.

## 5. Чеклист перед заменой ассета

**Панель**

- [ ] Размер квадратный (лучше 128 или 256).
- [ ] Рамка и углы целиком в зоне **25%** с каждого края.
- [ ] Центр без уникального орнамента.
- [ ] RGBA, края рамки без «дыр» в альфе (или осознанная прозрачность).
- [ ] Файл лежит как `assets/ui/panel.png`.

**Кнопки**

- [ ] Три файла одного размера.
- [ ] Без текста на картинке.
- [ ] Прозрачный фон снаружи формы.
- [ ] Имена: `button_normal.png`, `button_hover.png`, `button_active.png`.

После замены PNG пересборка кода не нужна — достаточно перезапуска
(ассеты читаются при `loadSkin` / старте рендера). На Android ассеты упакованы
в APK — нужна переустановка/Rebuild.

## 6. Связь с кодом (кратко)

| Что | Где |
|-----|-----|
| Загрузка PNG / fallback | `UiSkin::load` |
| Формула border | `min(w,h) * 0.25f` |
| Отрисовка 9-slice | `drawNineSlice` |
| Окно + title + inset | `UiSkin::BeginPanel` |
| Кнопка | `UiSkin::Button` |
| Вызов из UI | `GameUi::build` / `loadSkin` |

Архитектурный обзор: [ARCHITECTURE.md](ARCHITECTURE.md) §3 (UiSkin).

## 7. Если нужно другое соотношение рамки (не 25%)

Сейчас 25% зашито в `UiSkin.cpp`. Чтобы рисовать рамку 16 px на 128 (12.5%) или
произвольный border:

1. Либо менять множитель в коде,
2. Либо завести рядом `panel.slice` / константу в ассетах.

Пока художник должен **подстраивать арт под 25%**, а не наоборот.
